# Bin Day v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A HACS integration `bin_day` that fetches Simbio waste-collection dates, estimates missing dates, exposes sensors and reminder switches, sends optional phone reminders, and ships its own Lovelace card; published as `urosgruber/ha-bin-day` v0.1.0 and installed in the user's HA.

**Architecture:** A `Source` protocol (`async_fetch() -> dict[str, list[date]]`) feeds a `DataUpdateCoordinator`. Pure functions in `schedule.py` turn source dates plus stored history (`Store`) into one `Resolved` record per type. Sensors, the reminder scheduler and the card only read `Resolved` records. The card is a plain ES-module custom element served by the integration itself; all date math that depends on the time zone happens in Python, and the card reads it from attributes.

**Tech Stack:** Python 3.14, Home Assistant custom integration APIs (config flow, `DataUpdateCoordinator`, `Store`, `async_track_time_change`, issue registry), aiohttp (HA's shared session), pytest + `pytest-homeassistant-custom-component`, vanilla JavaScript (no build step) + `node --test`, GitHub Actions (hassfest, HACS validation, pytest), `gh`.

**Spec:** `docs/superpowers/specs/2026-11-09-bin-day-design.md`. Reference card code: the author's earlier hand-built dashboard card (not in this repository).

## Global Constraints

- GitHub: `urosgruber/ha-bin-day`, public, MIT licence.
- Domain `bin_day`, name "Bin Day", version `0.1.0`, `iot_class: cloud_polling`, `config_flow: true`, codeowner `@urosgruber`.
- HA minimum `2026.11.0` in `hacs.json`. Tests run against the HA version that the newest `pytest-homeassistant-custom-component` pins (2026.10.4 on 2026-11-09). If a release for 2026.11 exists at Task 1, pin that one instead.
- No personal data in the repository: no real address of the user, no entity IDs or phone names from the user's HA. Test address: "Ljubljanska cesta 1 A" (public WCS test case) or made-up ones.
- Simbio: `POST https://www.simbio.si/sl/moj-dan-odvoza-odpadkov`, form `action=simbioOdvozOdpadkov`, `query=<text>`. User-Agent `BinDay/0.1.0 (+https://github.com/urosgruber/ha-bin-day)`. Timeout 20 s.
- Type keys and defaults: `mko` → "Mixed waste"/"Mešani komunalni odpadki", `mdi:trash-can`, `#00a136`; `emb` → "Packaging"/"Embalaža", `mdi:recycle`, `#ffdd00`; `bio` → "Bio waste"/"Biološki odpadki", `mdi:leaf`, `#8d6e63`. Unknown `next_<key>` → name `<key>`, `mdi:delete`, next colour from `#1e88e5`, `#757575`, then repeat the list.
- Estimates: interval learned only from gaps 7–35 days, default 14; an estimate is trusted up to 2 intervals after the last real date; per-type switch "estimate" default on.
- Fetch times 06:00, 12:00, 18:30, at startup, and 30 min before each enabled reminder. Retry after 15 min, at most 4 times.
- Reminder defaults: evening 19:00 (on), morning-of 07:30 (on), morning-before 08:00 (off); reminders as a whole default off. "Today" is done at collection time + 1 h, or 12:00 if no collection time.
- Languages: English and Slovenian, chosen from `hass.config.language` (`sl*` → Slovenian, else English). Exact texts are in Task 7 and Task 8.
- Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Simbio returns an error page, HTML, `null` or a 5xx.** Expected: the fetch fails, all dates and estimates stay as they were, retries follow; nothing is deleted. → test `test_fetch_failure_keeps_data` (Task 4).
2. **Simbio corrects a date to an earlier day** than the stored future `last_real`. Expected: the new date wins and `last_real` moves back. → test `test_learn_correction_moves_last_real_back` (Task 3).
3. **Two types on the same day.** Expected: one reminder naming both, the card dot split in two colours, the headline "A + B". → tests `test_message_two_types` (Task 8), `model: two types same day` (Task 9).
4. **The browser is in another time zone than HA**, or the page stays open past midnight. Expected: the card follows HA's date, because it reads `today` and `days` from attributes and never uses the browser clock for dates. → test `model: uses server today, not browser clock` (Task 9); midnight refresh test `test_midnight_refresh` (Task 6).
5. **A chosen notify action disappears** (phone removed). Expected: the other targets still get the reminder; a warning is logged. → test `test_missing_notify_target_does_not_block_others` (Task 8).

### Task 3: Schedule logic (pure)

**Files:**
- Create: `custom_components/bin_day/schedule.py`
- Test: `tests/test_schedule.py`

**Interfaces:**
- Consumes: constants from Task 1.
- Produces:
  - `TypeHistory` (dataclass): `last_real: date | None = None`, `interval: int = 14`, `ever_seen: bool = False`, `warned: bool = False`; `to_dict()` / `from_dict(d)` (ISO dates).
  - `learn(hist: TypeHistory, real: list[date]) -> TypeHistory` (returns a new object).
  - `Resolved` (frozen dataclass): `date: date | None`, `estimate: bool`, `status: Literal["real","estimate","no_data","never"]`, `dates: tuple[date, ...]` (real future dates, or the one estimate), `days: int | None`.
  - `resolve(hist: TypeHistory, real: list[date], today: date, *, estimate_enabled: bool, interval_override: int | None) -> Resolved`
  - `done_at(collection_time: time | None) -> time` (collection time + 1 h, capped at 23:59; else 12:00)
  - `is_done(now: datetime, day: date, collection_time: time | None) -> bool` = `day == now.date() and now.time() >= done_at(collection_time)`.
  - `due_types(resolved: dict[str, Resolved], day: date) -> list[str]` (type keys whose `date == day`, in config order).

`learn` algorithm (the tests fix it):

```
dates = sorted(set(real))
if not dates: return hist (unchanged)
ever_seen = True; warned = False
# interval from consecutive future dates first
for a, b in pairs(dates): gap=(b-a).days; if 7<=gap<=35: interval = gap
newest = dates[-1]
if last_real is None:             last_real = newest
elif newest > last_real:
    gap = (dates[0] - last_real).days
    if 7 <= gap <= 35: interval = gap
    last_real = newest
elif newest < last_real and last_real >= dates[0]:   # correction to an earlier day
    last_real = newest
```

`resolve` algorithm:

```
step = interval_override or hist.interval
future = [d for d in real if d >= today]
if future: return Resolved(future[0], False, "real", tuple(future), (future[0]-today).days)
if not hist.ever_seen or hist.last_real is None: return Resolved(None, False, "never", (), None)
if not estimate_enabled: return no_data
n = max(0, ceil((today - last_real).days / step)); est = last_real + n*step
if (est - last_real).days > TRUST_INTERVALS*step: return no_data
return Resolved(est, True, "estimate", (est,), (est-today).days)
```

### Task 4: Coordinator, store, fetch times and repairs

**Files:**
- Create: `custom_components/bin_day/coordinator.py`

**Interfaces:**
- Consumes: `Source`, `SourceError`, `AddressNotFound` (Task 2); `TypeHistory`, `learn`, `resolve`, `Resolved` (Task 3).
- Produces:
  - `BinDayCoordinator(hass, entry, source: Source)` subclass of `DataUpdateCoordinator[BinDayData]`, `update_interval=None` (fetches are time-driven).
  - `BinDayData` (dataclass): `resolved: dict[str, Resolved]`, `today: date`, `source_ok: bool`, `last_success: datetime | None`.
  - `coordinator.history: dict[str, TypeHistory]` and `coordinator.source_warned: bool`, both loaded from and saved to `Store(hass, 1, f"bin_day.{entry.entry_id}")` with the payload `{"types": {key: TypeHistory.to_dict()}, "source_warned": bool}`.
  - `coordinator.type_keys: list[str]` (from `entry.data[CONF_TYPES]`, config order).
  - `async def async_fetch_now(self) -> None` (used by fetch times and Task 8).
  - `def recompute(self) -> None` (re-resolve with the current date, no network; used at midnight and at the done time).
  - `async def async_save(self) -> None` (persists history; Task 8 uses it after setting `warned`).
  - Repair issue id `address_not_found_{entry_id}` (translation key `address_not_found`).

Behaviour: on success, `learn` each configured type, save the store, `recompute`, clear the repair issue. On `SourceError`: keep `last real` from the store and the last source dates in memory (`self._last_real_dates`), `source_ok=False`, schedule a retry with `async_call_later(RETRY_DELAY)` up to `RETRY_MAX` per fetch slot. On `AddressNotFound`: create the repair issue, no retries. Fetch slots: `async_track_time_change` for each `FETCH_TIMES` entry, plus each enabled reminder time minus `PRE_REMINDER_FETCH` (read from options). Recompute at 00:00:05 and at `done_at(collection_time)`. All listeners are removed on unload (`entry.async_on_unload`).

  - returns `{title, state: "quiet"|"tomorrow"|"today"|"empty", accent: {bg, fg}|null, headline: {names: [..], icon, color, dateText, relText, prefix: ""|"TOMORROW"|"TODAY"}, rest: [{name, icon, color, dateText, relText}], noData: [names], strip: [{label, today: bool, dots: [{color, estimate}]}], footnote: bool}`.

Rendering rules (from the spec and the reference JS):
- `days` and `today` come from attributes; the browser clock is never used for dates.
- A type with status `never` is left out. `no_data` types go to a small "No data" / "Ni podatkov" line.
- If `done` is true, entries with `days === 0` are dropped.
- Headline group = all types with the smallest `days`; `state` = `today` if 0, `tomorrow` if 1, else `quiet`; `accent` = first group colour, `fg` `#1c1c1c` when the colour's relative luminance > 0.5, else `#ffffff`.
- Texts EN/SL: weekday long "Monday…"/"ponedeljek…", short "Mo…"/"po…", date "13. 11.", rel "today"/"danes", "tomorrow"/"jutri", "in N days"/"čez N dni", prefixes "TOMORROW"/"JUTRI", "TODAY"/"DANES", sub on due days "<long date> · until 11:00"/"· do 11:00" when `until`, footnote "* estimate – no data from the source"/"* ocena – vir nima podatka", empty "No collection data. Check the source."/"Ni podatkov o odvozu. Preveri vir podatkov.". `lang` = `hass.locale.language` starting with "sl" → SL, else EN.
- Styling: copy the CSS of the reference card, including the fixed icon sizes and the title in HA Heading style (`--ha-font-size-l`, `--ha-font-weight-medium`). Card background/text use `accent` when present, else theme variables. `getCardSize()` returns 3.
